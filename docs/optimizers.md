# 優化器：模型答錯以後，下一步要改多少？

## 先看懂一次更新，不急著背四種名字

CNN 裡有很多「權重」，可以想成很多可調整的小旋鈕。旋鈕改變，模型的預測就改變。**優化器的工作，是決定這一批照片看完後，每個旋鈕往哪邊轉、轉多少。**

- **Loss**：這一批答得有多不好，像一張需要降低的錯誤分數。
- **梯度 g**：每個旋鈕附近的斜率。正值表示權重再增加一點會讓 Loss 上升；負值表示權重再增加一點會讓 Loss 下降。這是局部資訊，不保證走很遠也一樣。
- **學習率 α**：控制更新的步伐。不是貓或狗的判斷門檻，也不是正確標籤。
- **優化器**：拿到梯度後，決定更新方法。

```text
看一批照片 → 預測 → 算 Loss → 算每個權重的梯度 → 更新權重
                                                         ↓
                                                   再看下一批
```

## 用一個旋鈕真的算一次

先用「讓數字 w 接近 3」的玩具任務，理解更新；這不是把動物標籤當成數字 3，也不是本專案的分類 Loss。

```text
錯誤分數：L(w) = (w − 3)²
梯度：    g = 2 × (w − 3)
```

目前 w=1：Loss=(1−3)²=4，梯度=2×(1−3)=−4。

用最簡單的 SGD，假設學習率 α=0.1：

```text
新權重 = 舊權重 − 學習率 × 梯度
       = 1 − 0.1 × (−4)
       = 1.4
```

更新後 Loss=(1.4−3)²=2.56，比原本 4 小。**梯度是負的，所以減掉負數，權重反而增加。** 我們沒有改答案 3，而是把目前的猜測從 1 移到 1.4。

如果 α=0.01，只走到 1.04；如果 α=2，會衝到 9，Loss 變成 36。這就是為什麼不是走越大步越好。這些數字只為方便算例，不是建議 CNN 使用的學習率。

## 公式符號小抄

| 符號 | 白話意思 |
|---|---|
| w | 某一個權重，也就是一個旋鈕的數值 |
| g | 目前這批算出的梯度，帶正負號的斜率 |
| α（alpha） | 學習率，控制步伐大小 |
| t | 第幾次權重更新；不是第幾個 epoch |
| u | 記住的更新步伐，帶正負號 |
| s、v | 記住的「梯度平方」平均；平方不分正負，用來估計大小 |
| m | 記住的梯度平均，保留正負方向 |
| μ、ρ、β | 保留多少舊紀錄的比例，例如 0.9 就是保留九成 |
| ε（epsilon） | 分母中的小數值，避免分母太小造成不穩定 |
| λ（lambda） | 權重衰減強度，控制往零縮多少 |

下面先只追蹤一個權重。真正 CNN 對大量權重分別做同樣運算；看懂單一權重，不代表可以直接算出 Accuracy。

## 1. SGD：照這次的斜率走

**一句話：這一批告訴我往哪改，我就按學習率改一小步。**

```text
w新 = w舊 − α × g
```

這就是前面的 1 → 1.4。它沒有替每個權重額外調整尺度；每個權重仍因自己的梯度不同而有不同更新量。

### 加上 Momentum：別每一批都忘記上一批

如果上一批與這一批都建議同方向，就保留一些前一次步伐。像推球時還留有上一下的慣性；若方向反覆變，正負步伐也可能抵銷。

```text
u新 = μ × u舊 + α × g
w新 = w舊 − u新
```

例如上一個步伐 u舊=−0.2、μ=0.9，這次 α=0.1、g=−4：

```text
u新 = 0.9 × (−0.2) + 0.1 × (−4) = −0.58
w新 = w舊 − (−0.58) = w舊 + 0.58
```

這個例子只示範動量加法，沒有權重衰減。Lab 的 SGD 使用 momentum=0.9，因此與完全沒有動量的 SGD 不同。

## 2. RMSprop：每個旋鈕先看自己最近的斜率大小

**一句話：有些權重的梯度常常很大，有些很小，先依各自最近的大小調整步伐。**

先把梯度平方，做一份「最近大小」的紀錄：

```text
s新 = ρ × s舊 + (1 − ρ) × g²
```

ρ=0.9 就是「九成舊紀錄＋一成這次的梯度平方」。再用它縮放更新：

```text
本次步伐 = α × g / √(s新 + ε)
w新 = w舊 − 本次步伐
```

分母較大會把這次更新縮得更多；分母較小則縮得較少。因為 s 也會跟著 g 改變，不能只看分子就判斷步伐。

例如從 s舊=0 開始，g=−4、ρ=0.9、α=0.1：s新=1.6；暫時忽略 ε，步伐≈−0.316，w 從 1 變成約 1.316。

這個數字示例沒有動量。**Lab 的 RMSprop 還加了 momentum=0.9**：

```text
u新 = μ × u舊 + 本次步伐
w新 = w舊 − u新
```

以上對應 Keras 2.15、centered=False，ε 放在平方根裡；本專案 ε=0.001，實際計算不能總是假裝它是零。自動調整尺度也不代表不必選學習率。

## 3. Adam：兩本筆記，一本記方向、一本記大小

**一句話：不要只聽這一批；參考最近常往哪走，再依最近梯度大小調整步伐。**

```text
m新 = β₁ × m舊 + (1 − β₁) × g       # 記方向
v新 = β₂ × v舊 + (1 − β₂) × g²      # 記大小
```

例如 β₁=0.9，就是把九成舊方向與一成新梯度混在一起。這份 m 與 SGD 的 u 定義不同，不能直接交換公式。

Adam 還會修正剛開始兩本筆記都是零造成的偏差。初學先記住更新結構：

```text
更新量 = 經早期修正的學習率 × 方向紀錄 / (√大小紀錄 + ε)
w新 = w舊 − 更新量
```

<details>
<summary>展開完整公式：對應本專案 Keras 2.15（amsgrad=False）</summary>

```text
mₜ = β₁mₜ₋₁ + (1−β₁)gₜ
vₜ = β₂vₜ₋₁ + (1−β₂)gₜ²
aₜ = α × √(1−β₂ᵗ) / (1−β₁ᵗ)
wₜ = wₜ₋₁ − aₜ × mₜ / (√vₜ + ε)
```

m₀=v₀=0，t 從 1 開始。上標 t 是次方，下標 t 是第 t 次更新。aₜ 是經早期修正的係數，不是另一個需要在介面填寫的參數。

例如第一步 g=−4、α=0.1，忽略極小 ε，更新量約 −0.1，所以 w 從 1 變成約 1.1。此例的數值與 SGD 不同，但不能只看一步就說哪種方法更好。

有些教材改寫成「偏差修正後的 m、v」，epsilon 的寫法可能不同；此處保留目前程式版本的運算位置。

</details>

Adam 並不是自動找到最佳答案，學習率太大仍可能失敗；也不保證比 SGD 好。

## 4. AdamW：Adam 更新以外，再把旋鈕往零拉一點

**一句話：先照 Adam 的方式學，同時額外限制權重長得太大。**

```text
w新 = (1 − α × λ) × w舊 − Adam更新量
```

α 是學習率，λ 是 weight_decay。公式使用同一個舊權重，表示衰減與自適應梯度更新分開處理。

例如 w舊=1、α=0.1、λ=0.01，Adam更新量=−0.1：

```text
只做 Adam： w新 = 1 − (−0.1) = 1.1
加上衰減：  w新 = (1−0.1×0.01)×1 − (−0.1) = 1.099
```

衰減只讓結果比 1.1 小一點，**不表示最後的權重一定比舊權重小**，因為學習的更新可能同時把它推大。λ=0 時，就沒有這項額外衰減。衰減可能幫助泛化，但太強也可能學不好。

## 四種方法先這樣分

| 方法 | 在最基本的更新外，多記什麼？ |
|---|---|
| SGD | 最簡單版只用目前梯度；加 momentum 時記上一個更新步伐 |
| RMSprop | 記最近梯度的大小，讓每個權重各自調整尺度 |
| Adam | 記最近方向與大小，另做初期修正 |
| AdamW | 與 Adam 相同，再分開加入往零縮小的力道 |

## 這份程式實際用了什麼

建立優化器的入口是 [tools/utils.py](../tools/utils.py) 的 `build_optimizer()`。以下對應已固定的 TensorFlow／Keras 2.15 環境：

| 優化器 | 由 YAML 控制 | 其他使用的值 |
|---|---|---|
| SGD | learning_rate、momentum、weight_decay | nesterov=False |
| RMSprop | learning_rate、momentum | rho=0.9、epsilon=0.001、centered=False |
| Adam | learning_rate | beta_1=0.9、beta_2=0.999、epsilon=0.0000001；程式不套用 YAML 的 weight_decay |
| AdamW | learning_rate、weight_decay | beta_1=0.9、beta_2=0.999、epsilon=0.0000001；不使用 YAML 的 momentum |

`momentum` 是 SGD／RMSprop 的設定，不會覆寫 Adam／AdamW 的 beta_1。Adam 雖然有梯度平均，也不是讀取同一個 momentum 欄位。

- `config.yaml` 是命令列入門範例，weight_decay=0，學習率=0.0001。
- `config_lab.yaml` 是介面基礎，momentum=0.9、weight_decay=0.0005；介面再覆寫模型、學習率與優化器。
- **目前 Lab 只有 SGD／AdamW 套用 weight_decay；Adam／RMSprop 不套用，非零時會提示。** 這是本專案的選擇，不表示 Keras 的其他優化器不能支援衰減。

## 如何公平比較與閱讀結果

1. 比學習率：固定模型、資料、優化器、batch、seed 與訓練預算，只改 learning_rate。
2. 比優化器：固定模型與資料，記錄 learning_rate、momentum、epsilon、weight_decay；不能只看優化器名稱。
3. 本專案比較的是「目前這四組優化器配方」。不同優化器的附加設定不同，**不能把分數差完全歸因於演算法本身**。
4. 若要專門研究演算法差別，可另設 weight_decay=0 的控制實驗；若要比較各方法可達到的表現，則給各方法相同調參預算，允許不同最佳學習率。
5. 看多輪 train／validation Loss、Accuracy、Macro F1 與逐類 Recall，低分也保留。高 Accuracy 但少數類別 Recall 很低，仍可能分類不均。
6. 最佳權重依十輪內的驗證 Accuracy 選出，並非依最高 F1 選出；不能各拿不同輪的最高指標拼成一筆結果。測試集留到選參數完成後，避免反覆使用測試成績挑參數。

目前只跑固定十輪、單一 seed 的參數格點；不能把這份結果當成所有優化器或模型的普遍排名。
